# Database Operations & Comprehensive Component Architecture

This document provides a guide to observing real-time background database operations in **EV Charging Demand & Grid Load Analytics**, followed by an explanation of every component, service, and data pipeline in the project.

---

## Part 1: How to Observe Background Database Operations

The project uses a **hybrid database architecture**:
- **PostgreSQL**: Relational schema, analytical SQL views, transactional triggers, session tracking, and role-based access control.
- **MongoDB**: High-cadence electrical telemetry stream (`grid_telemetry`) with semi-structured sensor readings.
- **Background Simulator**: Node.js/TypeScript daemon streaming electrical batches into MongoDB every 5 seconds.

Here is how you can observe all operations across each layer.

---

### 2. Observing PostgreSQL Operations via CLI

#### A. Watch Active Queries in Real Time
To see active queries, executing connections, and wait states:
```bash
psql -U yaswanth -d ev_charging_analytics -c "
SELECT pid, usename, client_addr, state, query_start, now() - query_start AS duration, query
FROM pg_stat_activity
WHERE datname = 'ev_charging_analytics' AND pid <> pg_backend_pid();"
```
Or continuously watch active operations every 2 seconds:
```bash
watch -n 2 'psql -U yaswanth -d ev_charging_analytics -c "SELECT pid, state, now() - query_start AS duration, query FROM pg_stat_activity WHERE datname = '\''ev_charging_analytics'\'' AND state != '\''idle'\'';"'
```

#### B. Check Real-Time Table Record Counts & Growth
```bash
psql -U yaswanth -d ev_charging_analytics -c "
SELECT
  relname AS table_name,
  n_live_tup AS estimated_rows,
  n_tup_ins AS inserts,
  n_tup_upd AS updates,
  n_tup_del AS deletes
FROM pg_stat_user_tables
ORDER BY n_live_tup DESC;"
```

#### C. Inspect Table Locks & Contention
```bash
psql -U yaswanth -d ev_charging_analytics -c "
SELECT
  t.relname,
  l.locktype,
  l.mode,
  l.granted,
  a.query
FROM pg_locks l
JOIN pg_stat_all_tables t ON l.relation = t.relid
JOIN pg_stat_activity a ON l.pid = a.pid
WHERE t.schemaname = 'public';"
```

#### D. View Audit Log Entries Generated by Admin Operations
Whenever an admin registers, deactivates, or modifies an entity, it is written to the audit log:
```bash
psql -U yaswanth -d ev_charging_analytics -c "
SELECT log_id, admin_id, admin_email, action, target_entity, target_id, details, created_at
FROM admin_activity_log
ORDER BY created_at DESC
LIMIT 10;"
```

### 3. Observing MongoDB Telemetry Operations

#### A. Tail MongoDB Container Logs
The MongoDB instance runs inside Docker (`ev-charging-mongo`). Tail all incoming operations, socket connections, and index operations:
```bash
docker logs -f ev-charging-mongo
```

#### B. Watch Incoming Telemetry Inserts in `mongosh`
Enter the MongoDB shell and watch incoming records from the simulator:
```bash
mongosh "mongodb://127.0.0.1:27017/ev_charging_analytics" --eval '
db.grid_telemetry.find({}, {
  station_id: 1,
  power_kw: 1,
  grid_load_kw: 1,
  voltage_v: 1,
  frequency_hz: 1,
  recorded_at: 1
}).sort({ recorded_at: -1 }).limit(5)'
```

#### C. Run the Project Telemetry Verifier
A dedicated verification script checks connection health, count, and latest readings:
```bash
node check-telemetry.mjs
```

#### D. Check Currently Executing MongoDB Operations
In `mongosh`:
```javascript
db.currentOp({ "ns": /^ev_charging_analytics\./ })
```

#### E. Enable MongoDB Database Profiler (Log slow/all queries)
To log all operations taking > 0ms into `system.profile`:
```javascript
use ev_charging_analytics
db.setProfilingLevel(2) // 1 = slow ops, 2 = all ops
db.system.profile.find().sort({ ts: -1 }).limit(10)
```

### 4. Observing the Background Telemetry Daemon

The background telemetry simulator runs as a detached process generating simulated electrical data.

- **Check Process Status**:
  ```bash
  npm run simulator:status
  # Output: [simulator] Simulator is RUNNING (PID: xxxxx)
  ```
- **Inspect Live Simulator Logs**:
  ```bash
  tail -f .simulator.log
  ```
- **Check Process State & Metadata (`.simulator.meta.json`)**:
  ```bash
  cat .simulator.meta.json
  ```
- **Stop or Start Daemon**:
  ```bash
  npm run simulator:stop   # Halts background streaming cleanly
  npm run simulator:start  # Launches daemon in background
  npm run simulator:once   # Runs exactly 1 synchronous tick across all stations
  ```

### Detailed Component Inventory

#### 1. Database Schema & Migrations (`database/`)
- [`database/postgresql_schema.sql`](file:///home/yaswanth/College/DBMS_Sem5/DBMS_miniproject/EV_Charging_Analytics/database/postgresql_schema.sql):
  Defines base DDL tables: `Charging_Station`, `Charger`, `EV`, `Charging_Session`, `Station_Capacity`, and relational foreign keys with `ON DELETE RESTRICT`.
- [`database/postgresql_sample_data.sql`](file:///home/yaswanth/College/DBMS_Sem5/DBMS_miniproject/EV_Charging_Analytics/database/postgresql_sample_data.sql):
  Initial seed baseline.
- [`database/migrations/002_analytics_views_and_triggers.sql`](file:///home/yaswanth/College/DBMS_Sem5/DBMS_miniproject/EV_Charging_Analytics/database/migrations/002_analytics_views_and_triggers.sql):
  - `v_station_metrics`: Aggregates active chargers, total sessions, cumulative energy (kWh), revenue, and capacity utilization.
  - `v_hourly_demand`: Splits sessions proportionally across each hour of the day.
  - `v_daily_demand`: Daily revenue, sessions, energy delivered with 7-day rolling metrics.
  - `v_overload_events`: Identifies snapshots where current load exceeds permitted capacity.
  - `check_station_capacity`: PL/pgSQL trigger preventing charger capacity from exceeding station power transformer ratings.
- [`database/migrations/003_users_and_sessions.sql`](file:///home/yaswanth/College/DBMS_Sem5/DBMS_miniproject/EV_Charging_Analytics/database/migrations/003_users_and_sessions.sql):
  Creates `app_user` (Argon2id password hashes, roles: `ADMIN`, `ANALYST`) and `auth_session` for server-side token management.
- [`database/migrations/004_session_detail_view.sql`](file:///home/yaswanth/College/DBMS_Sem5/DBMS_miniproject/EV_Charging_Analytics/database/migrations/004_session_detail_view.sql):
  `v_session_details`: Flattens EV model, registration, charger speed, and duration for fast querying.
- [`database/migrations/005_fix_station_capacity_guard.sql`](file:///home/yaswanth/College/DBMS_Sem5/DBMS_miniproject/EV_Charging_Analytics/database/migrations/005_fix_station_capacity_guard.sql):
  Hardens the capacity check trigger function during concurrent insertions.
- [`database/migrations/006_admin_activity_log.sql`](file:///home/yaswanth/College/DBMS_Sem5/DBMS_miniproject/EV_Charging_Analytics/database/migrations/006_admin_activity_log.sql):
  Immutable audit log recording admin email, action type (`CREATE`, `DEACTIVATE`, `DELETE`), target entity, and JSON payload.

#### 4. Security & Authentication Architecture (`src/lib/auth/`)
- [`dal.ts`](file:///home/yaswanth/College/DBMS_Sem5/DBMS_miniproject/EV_Charging_Analytics/src/lib/auth/dal.ts):
  Server-side **Data Access Layer**. Enforces role checks (`verifySession()`, `requireAuth()`, `requireRole()`) inside Server Components and API Route handlers.
- [`password.ts`](file:///home/yaswanth/College/DBMS_Sem5/DBMS_miniproject/EV_Charging_Analytics/src/lib/auth/password.ts):
  Argon2id cryptographic hashing with memory-hard work factors via `@node-rs/argon2`.
- [`session.ts`](file:///home/yaswanth/College/DBMS_Sem5/DBMS_miniproject/EV_Charging_Analytics/src/lib/auth/session.ts):
  Issues cryptographically secure random session tokens, stores them in `auth_session` with explicit expiration, and attaches `httpOnly`, `sameSite: "lax"`, and `secure` cookies.
- [`csrf.ts`](file:///home/yaswanth/College/DBMS_Sem5/DBMS_miniproject/EV_Charging_Analytics/src/lib/auth/csrf.ts):
  Validates `Origin` and `Referer` headers on all state-changing `POST`, `PATCH`, `DELETE` requests to prevent cross-site request forgery.
